## 开发理念与原则

### 核心信念
- **渐进式推进优于大爆炸式改动** - 小步修改，确保编译通过且测试通过
- **从现有代码中学习** - 实施前先研究和规划，遇到不会的请自行上网搜索
- **清晰意图优于巧妙代码** - 选择朴实明显的方案
- **简洁性原则** - 每个函数/类只负责单一职责，避免过早抽象，专注代码质量，不要写文档和测试类

### 实施流程
1. **理解** - 研究代码库中的现有模式
<!-- 2. **测试** - 先写测试（放在testDev文件夹），测试通过后清除测试文件 -->
3. **实现** - 编写最少代码使测试通过
4. **验证** - 自动进行功能验证，运行程序来验证各个功能是否正常
5. **修复** - 如果发现了bug或不正常的地方请自行修复

### 问题解决策略（最多3次尝试）
- 遇到bug请自行修复
- 如果发现缺少环境请自动从网上下载（例如：从github进行下载），并根据需要自行配置和搭建环境
- 3次失败尝试后停止并重新评估方案

## 项目管理规范

### 文件组织
- 如果你需要编写测试代码的时候，请单独建一个testDev文件夹并将所有临时代码或测试代码或自动验证代码放到testDev文件夹中
- 如果你要写日志或者.log之类的临时日志文件，请放到testDev文件夹中
- 当你需要删除文件时，或者我要求你删除文件时，你要将文件移动到回收站而不是删除
- 如果你要启动程序进行测试，需要你在测试前先检查一下当前目录内有没有那种去掉斜杠的带路径的空文件夹，这种可能是调用cmd指令之类的时候错误生成的文件夹，如果发现了就将错误的带路径的空文件夹移动到回收站

## 测试与验证

### 自动化测试
如果是java程序，那么自行编译测试，但是不要运行和占用端口

### 质量保证
- 当你编写代码完成时，要检查编写的代码是否存在作假行为（即：未按照用户要求实现代码并采取其他方式试图蒙骗用户），如果存在作假则需要重新编写代码，修正作假行为

### 完成定义
- ✓ 测试编写完成且通过
- ✓ 代码运行正常，无bug
- ✓ 无作假行为
- ✓ 测试文件都在testDev文件夹中
